# ChessAiBot Direction Clarification

ChessAiBot should still include enterprise-level backend engineering, but it should not be designed as a web app.

The project should be a local-first Python software system with a backend-style architecture.

Core direction:

> Enterprise backend engineering, but not a web product.

This means the project should still include:

* Service layer
* Repository layer
* MySQL persistence
* SQLAlchemy models
* Alembic migrations
* Background workers
* Benchmark pipeline
* Report generation
* Logging
* Configuration management
* Error handling
* Docker Compose
* Automated testing
* CI/CD
* Optional local API server

But the project should avoid becoming mainly about:

* Web UI
* User accounts
* Online rooms
* Public website deployment
* SaaS-style cloud hosting
* Frontend product design

FastAPI can still be included, but it should be treated as a local backend service or local engine server, not as the main product.

The main software workflow should be:

1. Start local infrastructure with Docker.
2. Run ChessAiBot locally through CLI or local service.
3. Simulate AI-vs-AI matches.
4. Save games, moves, matches, benchmarks, and reports into MySQL.
5. Generate analysis reports.
6. Use tests, logs, and documentation to keep the project maintainable.

The final goal is not to build a website.

The final goal is to build a practical local Python AI software system with enterprise backend architecture.
